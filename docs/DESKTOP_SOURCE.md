# Model 0.18：可选 Drive 桌面版模型来源

## 本次增加什么

保留原有 Google Drive API 模式，并新增一个**独立、可切换、只读**的模型来源：由 Runtime 读取同一台 Windows 电脑上 Drive 桌面版提供的目录。

桌面版模式不获取、伪造或传送网页 OAuth 令牌，也不需要 Cloudflare OAuth Worker。读取权限来自你在桌面版 Drive 的登录和 Windows 原生目录选择；API 模式继续使用原有 OAuth，不会自动切换到另一账号或来源。

这不是把模型运算交给 Google Drive。计算仍在 Runtime 所在电脑的 CPU/GPU 上，原有硬件与模型专用适配器限制不变。

## 操作

1. 完整解压 0.18 安装包，运行 `runtime/Install.cmd` 更新 Runtime。不要把新网页与旧 0.17 EXE 混用。
2. 在同一个 Windows 用户会话下登录 Drive 桌面版，确认资源管理器能打开模型目录。
3. 打开本机网页 `http://127.0.0.1:8765/`，在“模型来源”选择 **Drive 桌面版目录（无需网页 OAuth）**。
4. 点击 **选择桌面版模型目录**，在 Windows 弹出的窗口里选择 `AI-Model-Vault`。盘符不写死；示例 `G:\My Drive\AI-Model-Vault` 不是对你实际路径的判断。也支持放在其他盘的镜像目录。
5. 选择完成后会扫描。以后重新启动 Runtime 或改变目录内容，应点击 **扫描目录**；扫描失败不会发布半份“完整”索引。
6. 从原有模型卡片启动。聊天、Embedding、Reranker、已接入的图像任务和原生 OCR/时序/完整视频包，沿用各自工作区与运行接口。缺文件、缺适配器或资源不足仍会拒绝启动。
7. 切回 **Google Drive API（原模式）** 可继续使用原流程。请先停止已加载模型和运行中的任务；API 与桌面版索引分开保存，远程 Runtime 的桌面索引也单独隔离。

第一次授权目录必须在该主机的本机网页完成，远程网页不能传入任意系统目录，也不能静默弹出对方电脑的选择窗口。选择器只选择现有目录，不新建目录。

## 文件和缓存

**扫描阶段：** 只枚举文件名和文件元数据，并读取最多 16 MiB 的 `model_metadata.json`；不会遍历读取整个模型权重内容。流式目录枚举可能使 Drive 拉取云端目录元数据，这不等于权重下载。

**启动阶段：** 仅把选中任务需要的文件读入已有 Runtime 缓存（默认 `D:\Model`）。数据先写 `.part`，文件大小、扫描版本和完整复制的 SHA256 记录就绪后才提交正式缓存。再次启动复用已完成副本。SHA256 是本次复制内容的校验记录，不是自动获得的模型发布者签名。

**中断恢复：** 保留未完成的副本；重试时先逐段比较已复制部分与当前源文件，再继续追加，不仅依据 `.part` 长度判断。源文件版本改变则要求重新扫描，并使用新缓存身份。

**只读边界：** 不向所选目录写文件，不改名、移动或删除 Drive 原件。缓存删除只清理 Runtime 自己的缓存记录，不操作同步源。缓存目录不能与模型源互相包含。

这版选择稳定的完整文件缓存路径，**没有启用“直接在 Drive 虚拟盘 mmap、保证不另占空间”的模式**。Drive 在线访问文件首次读取仍可能由桌面客户端下载，并占用其自身缓存；加上 Runtime 副本可能需要两份空间。磁盘预检覆盖 Runtime 缓存盘，不能保证桌面版 Drive 自身缓存盘空间足够。

## 目录结构与范围

继续使用 `AI-Model-Vault` 的分类目录，例如 `llm/`、`rag/`、`ocr/`、`timeseries/`、`image_base/`、`video_ultra/`。保留根目录的 `model_metadata.json` 以识别专用模型。没有登记表时明确提示，并只按现有目录/扩展名规则识别；不臆造模型家族。

一次授权一个源目录，**不自动扫描所选目录之外的兄弟目录**。API 模式原有的外部链接目录不会被当作本机目录授权。符号链接与 Windows junction 跳过并报告；正常云端占位文件的 reparse 标志不等于符号链接，不能一律屏蔽。

仅有登记项、空文件或未完成下载文件不会变成已就绪模型。缺少的模型仍需完成权重准备并同步到所选目录；桌面模式不会仅因缺权重而请求网页 OAuth。

## 远程 Runtime

桌面版路径始终属于 **Runtime 主机**，不是浏览器所在电脑。浏览器连接另一台 NVIDIA Runtime 时，需在那台主机上授权它自己的 Drive 桌面版目录；不会把当前电脑的盘符传过去冒充远程文件。私有 HTTPS 与 Runtime 令牌仍按原规则使用。

## 配置及接口

Windows 配置在 `%LOCALAPPDATA%\JvustModel\desktop-source.json`，不包含 Google 令牌。仅为源码开发和自动测试提供 `MODEL_DESKTOP_CONFIG` 环境变量；这是本机进程设置，不是网页可写的任意路径参数。

- `GET /v1/desktop/status`：配置是否可用、扫描阶段及 Runtime 实例标识。
- `POST /v1/desktop/pick`：仅本机同源网页，调用 Windows 原生选择器。
- `POST /v1/desktop/scan`、`POST /v1/desktop/stop`：扫描与取消。
- `GET /v1/desktop/snapshot`：当前完成的索引；不返回主机绝对源路径。
- `POST /v1/desktop/probe`：对当前索引中的单个文件最多读取 4096 字节，只返回字节数，不是完整模型验收。

模型启动继续使用已有接口。`DesktopAwareCache.access_token` 仅对当前扫描中有效的本地文件句柄免除上游 OAuth；混用本地与 API 文件会被拒绝，云端文件仍需要原有授权。

## 验证边界

本地新增 43 项文件系统/HTTP 测试，完整 Python 套件共 196 项。覆盖只读扫描、目录范围、句柄伪造、文件变化、取消后续读、缓存复用、缓存删除、API 授权保留和远程选择器拒绝。

浏览器测试分别记录是否使用真实 localhost HTTP 或离线模拟传输，不把模拟当作联网验收。Windows CI 另用官方 Qwen 小模型验证本地目录 → 冷缓存复制 → 聊天 → 热缓存复用，模型推理是真实的，但目录仍是临时文件系统夹具。

**本轮没有操控或实测你的 Drive 桌面版挂载，没有完成你的电脑或 NVIDIA 双机验收。** 实际挂载、掉线、同步状态和占位文件召回仍需在目标设备确认；不能把普通目录测试说成 DriveFS 全面兼容认证。
